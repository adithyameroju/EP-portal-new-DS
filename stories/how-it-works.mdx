<h2><span class="n">2.</span> The self-correcting loop</h2>
<p class="lede">Every build makes the system a little tighter. A designer builds, the
   assumptions are captured, the output is scored, drift is detected and clustered,
   a fix is <em>proposed</em> — and only after the owner approves does a spec tighten,
   so the next build drifts less.</p>

<h2><span class="n">4.</span> Where the human decides — and why</h2>
<p class="lede">The single rule that governs everything: <strong>the system proposes,
   the owner approves — it never invents an opinion.</strong> An honestly flagged gap
   ("no source decides this") beats a fabricated rule, because a fabricated rule is
   one Cursor would then follow literally.</p>
<div class="grid two">
  <div class="card"><h4>The owner approves…</h4>
    <p>· every spec tightening the loop proposes<br>
       · every new/edited spec, meta anti-pattern, SOP wording<br>
       · migration component/token mappings below confidence<br>
       · any consumer repointing or deletion during migration<br>
       · the semver policy, and any registry publish</p></div>
  <div class="card"><h4>…and why it's built this way</h4>
    <p>Compass has no legacy voice to draw opinions from yet — they form through real
       product work, never invention. So every meta entry cites a spec or is omitted;
       every decision the specs don't resolve renders as a visible
       <strong>"needs owner decision"</strong> flag, not a guess. The prescribe step
       enforces this in code: it quotes existing rules, and refuses to draft new ones.</p></div>
</div>
