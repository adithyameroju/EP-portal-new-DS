One-time setup — about five minutes

Before you start

  • Acko VPN / network — Compass tokens come from Acko's internal Nexus registry, only reachable on the Acko network.
  • GitHub access to ackotech/enterprise-compass-in-loop (ask the design-system owner if you get an access error).
  • Cursor installed.

1 · Paste the setup rule into Cursor (once)

Cursor → Settings → Rules → paste this. You do this a single time; everything after ships with the repo, so you never re-paste.

Using Compass in Loop — setup bootstrap (Cursor Settings → Rules)

Activate this rule ONLY when the user's message begins with the exact phrase
"Using Compass in Loop" (e.g. "Using Compass in Loop, build a signup screen").
Otherwise ignore this rule completely. The user is a designer, not a developer —
narrate briefly in plain English, and when a command fails, explain why first.

inside it, the repo's own CLAUDE.md and .cursorrules AUTO-LOAD and carry the full

3. After install, tell the designer to open the cloned folder as their Cursor

2 · What happens on your first prompt

Open an empty folder in Cursor and type, e.g., Using Compass in Loop, build a signup screen. The rule does the rest: it detects whether you're set up, clones + installs if not, verifies the setup (audit runs, brand font wired, app boots), and only then builds. You do nothing but watch and answer its questions.

When it fails — and what to do

  • E404 @acko/enterprise-tokens / ETIMEDOUT / ENOTFOUND nexus-dev.acko.in → you're off the Acko network. Connect to the Acko VPN, then say "Using Compass in Loop" again.
  • git auth failed / repo not found → you don't have access to the ackotech GitHub org yet. Ping #design-system-feedback.
  • Anything else → paste the error into #design-system-feedback; the owner watches it.

3 · Optional — the “Compass Feel” craft pack

Short craft guides (typography voice, spacing rhythm, density, motion restraint, form patterns, do/don't) distilled from the Compass specs. The build rule reads them before generating, so your output feels more on-brand. It's craft only — it never overrides the enforced tokens/components/specs.

Cursor (primary): unzip to ~/compass-feel/ (macOS/Linux) or %USERPROFILE%\compass-feel\ (Windows). Claude Code: ~/.claude/skills/compass-feel/. Per-designer, works across all your projects.

Build with Compass

Three ways in. Each starts with a phrase. The AI stays on Compass components + tokens and ends with a “What I assumed” list — read it, that's where you confirm or correct its guesses.

Prompt → build

Say: Using Compass in Loop, build a <screen>

  1. Describe the screen in plain words.
  2. The AI builds it from Compass components.
  3. It ends with “What I assumed”.
  4. Confirm / correct; it captures the build.

Good output: real Compass components (Card, Field, Button), semantic tokens, 0 audit errors.

Figma frame → build

Say: Using Compass in Loop, build this Figma frame …

  1. Connect the Figma MCP (Cursor → the Figma connector).
  2. Point it at the frame.
  3. It maps frame values onto Compass tokens/components.
  4. The “What I assumed” list is longer here — every mapping is a choice.

Good output: values mapped to tokens, and anything that didn't map cleanly surfaced as a question — never silently guessed.

Migrate a codebase

Say: Migrate this project to Compass using the compass-migrate skill

  1. Open the existing project.
  2. The skill inventories foreign components.
  3. It writes -compass variants + reports.
  4. It STOPS before deleting/repointing — your call.

Good output: heavy flagging is the tool working — a long needs-decision list means it refused to silently mis-map.

See your score — /compass-health

After building, run the app and open http://localhost:3000/compass-health — no terminal needed. It scores only your files:

  • Token discipline — hard-coded colors/sizes. Errors here are the only hard gate (they block a commit); fix them first.
  • Compliance score — advisory. Warnings are signals, not blockers; each one has a “To fix, prompt Cursor:” line you can paste back.

Rule of thumb: token audit at 0 errors → you can ship. Warnings are worth a look but never block you.

Work on a branch — never main

  1. Before building: git checkout -b <your-name>/<feature>
  2. Build. Capture happens automatically.
  3. End of day: git push -u origin <your-branch> — every day, even if unfinished. This is how your work + drift data reach the team.
  4. Never push to main; open a PR when a feature is ready.
